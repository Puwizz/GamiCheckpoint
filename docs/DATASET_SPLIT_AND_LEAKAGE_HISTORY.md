## 1. บทนำและปัญหาตั้งต้นของการแบ่งชุดข้อมูล (Background & Motivation)

ในการฝึกสอนโมเดล Computer Vision สำหรับงานตรวจจับขั้นตอนการพับกระดาษ (Origami Checkpoint Verification) ข้อมูลภาพถ่ายถูกสกัดมาจากวิดีโอที่มีการบันทึกต่อเนื่อง (Frame Rate 3.33 FPS หรือทุก 0.3 วินาที) ในสถานที่และสภาพแวดล้อมที่แตกต่างกัน

หากการแบ่งชุดข้อมูลระหว่าง **Train (ฝึกสอน)**, **Val (ตรวจสอบ)**, และ **Test (ทดสอบจริง)** ไม่ได้รับการออกแบบอย่างรัดกุม จะเกิดปัญหา **Data Leakage (การรั่วไหลของข้อมูล)** ส่งผลให้ตัวเลขประเมินความแม่นยำ (mAP) สูงเกินจริง แต่เมื่อนำไปใช้งานจริงกับผู้ใช้ในห้องใหม่ โมเดลจะไม่สามารถทำงานได้

## 2. ตารางเปรียบเทียบวิวัฒนาการการแบ่งชุดข้อมูลในแต่ละยุค

| ยุคการทดลอง | วิธีการแบ่ง (Partitioning Method) | การกระจายตัวของเซสชัน | สัดส่วน Train / Val / Test | การประเมินผลเชิงวิศวกรรม |
|---|---|---|:---:|---|
| **Classification Era**<br>*(MobileNetV2)* | **Session Split ดั้งเดิม**<br>(แยกตามโฟลเดอร์เซสชัน) | Train: `001, 003, 004`<br>Val: `002, 006`<br>Test: `005` | Train ~60%<br>Val ~20%<br>Test ~20% | **ปลอด Leakage 100%** มีระบบตรวจ SHA-256 Hash แต่โมเดลมี Background Bias จากภาพรวมทั้งเฟรม |
| **Run 5 & Run 6**<br>*(Roboflow Seg)* | **Flat Uniform Random Split**<br>(สุ่มกระจายระดับไฟล์ภาพเดี่ยว) | ทุกเซสชัน (001–006) ถูกสับกระจายปนกันในทุก Split | **Train: 70%** (3,295 ภาพ)<br>Val: 20% (941 ภาพ)<br>Test: 10% (471 ภาพ) | **Data Leakage รุนแรง:** เฟรมวิดีโอห่างกัน 0.3s ของห้องเดียวกันกระจายอยู่ทั้ง Train และ Val ทำให้ได้ mAP 97% ลวงตา |
| **Run 7 & Run 8**<br>*(Session Split แรก)* | **Strict Session Split**<br>(แยกห้องเด็ดขาดเพื่อแก้ Leakage) | Train: `001, 002, 004`<br>Val: `003`<br>Test: `005, 006` | **Train: 27.4%** (1,292 ภาพ)<br>Val: 30.6% (1,441 ภาพ)<br>Test: 41.9% (1,974 ภาพ) | **ปลอด Leakage 100% แต่สัดส่วนผิดเพี้ยน:** ชุด Train ได้ข้อมูลน้อยเกินไป (แค่ 27%) ทำให้ Test แสงส้ม (005) ตก |
| **Run 9 (ปัจจุบัน)**<br>*(Balanced Split)* | **Balanced Session Split**<br>(จัดสรรเซสชันตามความยาววิดีโอ) | Train: `001, 002, 003, 005`<br>Val: `004`<br>Test: `006` | **Train: 70.0%** (3,296 ภาพ)<br>Val: 17.2% (811 ภาพ)<br>Test: 12.7% (600 ภาพ) | **สมบูรณ์แบบ:** ได้สัดส่วนสากล 70/17/13, ปลอด Leakage 100%, และ Train มีข้อมูลครบทุกสภาพแสง |

## 3. การวิเคราะห์สาเหตุเชิงลึกของสัดส่วนผิดเพี้ยนใน Run 7 & 8 (Root Cause Analysis)

สาเหตุที่ใน Run 7 และ Run 8 ชุดข้อมูล Train ถูกกดลงไปเหลือเพียง **27.4%** เกิดจาก **"ความไม่เท่ากันของความยาววิดีโอดิบในแต่ละเซสชัน"**:

### 3.1 จำนวนเฟรมดิบและภาพที่สกัดได้ต่อเซสชัน:
* `session_001_night_Xplor`: เฟรมดิบ 206 เฟรม $\rightarrow$ คัดเลือกได้ **94 ภาพ** (v3 ขยายเป็น **238 ภาพ**)
* `session_002_noon_Xpolr`: เฟรมดิบ 207 เฟรม $\rightarrow$ คัดเลือกได้ **107 ภาพ** (v3 ขยายเป็น **243 ภาพ**)
* `session_004_train_blkwin_daylight`: เฟรมดิบ 2,690 เฟรม $\rightarrow$ คัดเลือกได้ **331 ภาพ** (v3 ขยายเป็น **811 ภาพ**)
* `session_003_val_floor_night_roomlight`: เฟรมดิบ 2,140 เฟรม $\rightarrow$ คัดเลือกได้ **595 ภาพ** (v3 ขยายเป็น **1,441 ภาพ**)
* `session_005_test_orgnight_roomlight`: เฟรมดิบ 2,338 เฟรม $\rightarrow$ คัดเลือกได้ **578 ภาพ** (v3 ขยายเป็น **1,374 ภาพ**)
* `session_006_noon_floor`: เฟรมดิบ 874 เฟรม $\rightarrow$ คัดเลือกได้ **258 ภาพ** (v3 ขยายเป็น **600 ภาพ**)

### 3.2 ผลกระทบของการจัดกลุ่มแบบเดิม:
เมื่อกำหนดกฎ `Train = 001, 002, 004` โดยดูจากจำนวนเซสชัน (3 ใน 6 เซสชัน):
* บังเอิญว่า `001` และ `002` เป็นเซสชันที่สั้นที่สุดในโปรเจกต์ (มีภาพรวมกันแค่ ~481 ภาพใน v3)
* ส่งผลให้ชุด Train มีภาพรวมเพียง `238 + 243 + 811` = **1,292 ภาพ (27.4%)**
* ในขณะที่เซสชันใหญ่ที่สุดสองตัว (`003` และ `005`) ซึ่งมีภาพรวมกันเกือบ 60% ของทั้งโปรเจกต์ ถูกนำไปขังไว้ในชุด Val และ Test ทำให้โมเดล **ขาดแคลนข้อมูลในการฝึกสอนอย่างรุนแรง**
